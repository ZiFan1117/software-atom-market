# 研究空白与实验设想

> 定位：若要走学术路线，这里是把上面所有讨论**变成可发表的科学问题**的起点。审稿人会问"你的贡献是什么"，答案在这里。

## 1. 研究问题（一句话可答的形式）

**RQ**: 在"人类意图 + 大模型组装"的软件开发范式下，**能力砖的粒度**与**契约的类型化程度**如何影响：
(a) 非程序员的任务完成率与学习成本；
(b) 大模型选砖与接线的准确率；
(c) 拼装期即可发现错误的比例（vs 运行期）。

## 2. 为什么现在没有答案（你论文"研究动机"三连）

1. **粒度从未被形式化**：UNIX 的 "do one thing well" 是文化口号，没有度量、没有实验；模块化理论（Parnas）谈的是"信息隐藏"，不谈"多小算小"。
2. **老方案缺拼装者**：语义 Web 服务（OWL-S/WSMO）想机器自动组合服务，死在标注成本；mashup 想让人拼，死在接口异质。两者都缺一个"能当胶水的语义匹配器"。
3. **新方案缺理论**：2023 后的工具库研究（Toolformer/Gorilla/ToolLLM/τ-bench）都在做"更多工具、更准检索"，**没有人系统控制"工具粒度"这个自变量做对照实验**。

## 3. 可检验假设（写进论文前先想清的可证伪命题）

- **H1（能力原子假设）**：对非程序员，把任务切到"一次意图"级（capability atom）比切成实现原语级或整任务级，任务完成率更高、完成时间更短。对照：Wong & Hong 2007 的失败记录（原语级失败）+ 认知组块理论。
- **H2（契约类型化假设）**：拼装期 schema 校验可把"接口不匹配"错误从运行期移到拼装期，显著降低试错成本（对比 UNIX 弱类型文本流的运行期炸）。
- **H3（AI 检索假设）**：AI 在"粒度匹配用户意图"的商店里选砖准确率，显著高于"纯原语商店"——原语越多，检索混淆率越高（受 Gorilla/τ-bench 结果启发）。
- **H4（回填收敛假设）**：带"组合→验证→回填"闭环的商店，其"重复实现浪费"随使用次数收敛（新任务更多命中已验证砖，而非现场生成）。

## 4. 实验设计（两翼）

### A. 人类实验（CHI/ICER 风格）
- **自变量**：粒度水平（实现原语 / 能力原子 / 整任务）、契约呈现方式（有 schema 校验提示 vs 无）。
- **被试分层**：程序员 / 非程序员（≥20/组）。
- **任务集**：一组生态任务（读表、抽取、换算、汇总、发送），难度控制。
- **因变量**：任务完成率、完成时间、尝试次数、SUS 可用性、NASA-TLX 负荷、（学习曲线=第二批任务相对第一批的提速）。
- **预期对照物**：mashup 时代的失败基线可作背景引用。

### B. Agent 实验（软件工程/LLM 基准风格）
- 构造 **GrainBench**（名称暂定）：同一批任务，三套货架（原语级/能力级/复合级），同一 LLM 装配工。
- **度量**：工具选择准确率（retrieval hit rate）、接线图一次性通过率（拼装期 0 报错）、完成端到端成功率、平均执行轮数。
- **基线**：Gorilla 的 APIBench、ToolLLM、τ-bench 数据可作参照系。
- **可发表点**：首次把"粒度"作为受控自变量跑 LLM 工具组装——目前没人这么跑。

## 5. 相关性判断

- 这一主题横跨 **软件工程（复用/组件）** 与 **HCI（终端用户开发）** 与 **LLM 智能体**。
- 可能 venue 倾向：
  - HCI：CHI / ICER / IEEE VL/HCC（EUD 主阵地）。
  - SE：ICSE / FSE / IEEE Software（实践导向更友好）。
  - AI+SE：ICLR/NeurIPS 的 agent 工具向（若重心在 H3/H4 与 GrainBench）。
- 你的本体背景加分点：可加一条"**静态契约（本体式 schema） vs 模型语义匹配**"的对照，接回语义 Web 服务谱系（`02` §6），这是少有人走、且你最独特的切入。

## 6. 下一步（如果你认领这个空白）

1. 定靶：先决定主 venue 是 HCI 型（人类实验为主）还是 SE/AI 型（基准为主），两者工作量差异大。
2. 先跑 H3 的微型预实验（最便宜）：10~20 块砖两种粒度货架 + 一个 LLM，数选砖命中率——有数就能支撑立项。
3. 人类实验（H1/H2）适合放到有原型后（见 `03` MVP）做用户研究。
