# 对外叙事：我们要说明的几件事（v0.1）

> 用途：一段话讲清"这个项目在说什么"。供演讲开场、README、投稿 related work 复用；各条对应仓库内文档，深入自取。

## 一句话

别再让人类和大模型把最多的算力与心智，一遍一遍花在**重写同一个轮子**上。

## 我们要说的几件事

**1. 问题定位：重复造轮子不是个别坏习惯，是结构性浪费。**
现在世界上大量的代码、逻辑、工具，是同一件事被反复重新实现；AI 时代的"逐行生成"更是把这种重复放大成每次全新即兴。克隆研究证实人类生态本就在复制，LLM 生成又把分母推高几个量级。（→ `docs/02` §3）

**2. 软件的本质位置：它是"人控制/改变物理世界"的方式之一。**
芯片、电路、机械——都是人对物理世界自动化控制的通道；软件也一样。既然如此，它就**理应像物理世界一样有可复用的标准件**，而不是每次从矿石开始冶炼。（→ `docs/01`）

**3. 主张：把能力做成"可原子化、可拼接"的底板。**
以"与用户一次意图对齐的最小能力单元"（Atom）为积木——接口统一、黑盒封装、带验证。大家拼，不重造；拼的自由度来自组合拓扑，不来自把砖切得更碎。（→ `docs/01` §4，`docs/03`）

**4. 创造性的位置：创造在"组合与框架层"，不在原子内部。**
AI（和人）的创造性应花在**怎么拼、拼成什么、提出什么新框架**上；**框架本身也是原子化的积木**。单个原子内部的"聪明"不是重点；真正属于"另一层"的是算法/实现的深度优化，那不属于原子外延，而是 L2/L3 的进化。（→ `docs/06` 分层）

**5. 怎么落地：接口 + 详尽的"内部怎么运行" + 副作用警告，写到"拿来即用"。**
每个原子 = 契约（`intent` + `input`/`output` 形状）+ 四节详情（怎么做/边界/示例/图）+ `side_effects` 警告 + `tests`。写清楚到任何一个人或 Agent **拿到就能跑通最小验证（MVP）**——MVP 一旦成立，后续工作全部在其上开展，省掉的是大部分重复开发与试错。（→ `spec/detail-convention.md`）

**6. 量化目标：解决 90% 以上的重复造轮子问题。**
把"同一件事反复实现"从常态压到 10% 以下：默认先检索公共底座，命中即复用；没命中的沉淀回填，让底座越用越厚。（→ `docs/03` §5 回填闭环）

**7. 一个工作习惯：做事的路上，顺手沉淀成原子并开源。**
每完成一段可复用能力，就在过程中把它打成原子化包公布出来，进公共底座供全世界共同使用——让"贡献"发生在劳动的同时，而不是事后补课。（→ `CONTRIBUTING.md`）

**8. 诚实的边界。**
我们不承诺消解"本质复杂度"：真正的算法创新、领域新知仍在，且属于更高价值层。我们消解的是**偶然复杂度 / 重复实现**，把人类与 AI 的算力还给创造本身。（→ `docs/01` §8，`docs/02` §2）

## 串成一段（30 秒版）

> 软件是人改变物理世界的通道，但它今天像"每次都从矿石炼钢"——同样的轮子被人类和 AI 一遍遍重写，消耗着最多的算力与心智。我们把能力做成"可原子化、可拼接的底板"：每个原子带统一契约、详尽的运行说明与副作用警告，任何人和 AI 拿来即可跑通最小验证。创造性发生在组合与框架层，框架本身也是原子。目标：把重复造轮子的比例打到 10% 以下——做事时顺手把沉淀的原子开源，让底座越用越厚。
